# v16 AC4 / C26：被动弃牌由本人选择

2026-09-08；覆盖英魂与悲歌梅花的“令其弃置牌”后续效果。英魂来源为 `card__hero__wu.md:279`，悲歌为 `card__hero__neutral.md:391`；`glossary__zone.md:80` 的“角色的牌”包含手牌、装备，判定区牌不属于角色的牌。

旧英魂仅从目标手牌用AI估值自动弃牌，既缺本人决策，也遗漏装备。旧悲歌梅花直接两次随机拆来源的牌，使用的是他人弃置目标牌的路径，未让受影响角色决定自己弃哪些牌。

## 实现

新增 `src/engine/forced-discard.js`，英魂完成规定摸牌后、悲歌完成梅花判定后进入同一个 `effect-discard` 响应帧。UI复用既有 `god-choice` 包装和卡牌选择面板，子类型 `effect-discard`；没有新增 pendingChoice kind 或 npm 依赖。唯一装配增量是给标准技能域传入现有 `GodChoices`。

- 受影响者为玩家时默认开必选窗口，列出自己的全部手牌和装备，装备标注区域；由本人精确选择 `cardIds`。禁止放弃；牌不足时弃当前全部可选牌，无牌时直接结束。
- AI座席、AI模拟照常自动决定自己的弃牌；显式 `skillPreferences.effectDiscard = 'auto'` 可关闭玩家提示。没有把“引擎测试”作为隐形跳过提示条件。
- 先验证数量、去重及所有ID均属于当前手牌/装备，再一次性取出整组选牌并提交弃牌。缺ID、重复ID、他人手牌、判定区牌、过期令牌或放弃决策均拒绝，整个状态不发生部分付款。
- 整组牌先扣除，装备失去时机按已提交事件序列逐项执行，再通知一次失牌（屯田）。游标和已通知标记先落帧再开子窗；JSON恢复不重复付款、英魂摸牌、白银狮子回血、枭姬摸牌或屯田判定。
- 英魂子窗保持准备阶段暂停，到本人弃牌及插入判定全部结束才进入正常摸牌；悲歌的外层伤害后帧先等待此窗。技能来源失技不会取消已经发动的后续效果；真实终局取消未回答的弃牌，不继续扣牌。

## 独立支付复核

响应域代理对新付款实现做独立跨审，发现首件装备的枭姬摸牌会把整组成本从弃牌堆洗回手牌；若下一件失装事件按 `game.discard.find(id)` 查找，其白银狮子回血及第二次枭姬都会被吞掉。测试真实从英魂进入，空牌堆/空弃牌堆，玩家选择青釭剑＋白银狮子：修复前体力2、枭姬一次；应为体力3、枭姬两次。

修复为付款时保存独立可序列化的装备失去事件牌面快照，后续事件只认已经成立的时机，不依赖实体牌仍处于弃牌堆。实体牌继续由既有CardRuntime移动，无复制实体入区。独立 `tests/v16_ac_payment_crossreview.test.mjs` 的 forced-discard 场景修复后通过；其缔盟同根因由对应域修复。随后独立JSON空堆测试又发现游戏随机函数不被JSON保留，导致洗牌抛错；主审在实际洗牌口复用既有randomSuit的可复现回退原则修复，不由测试重新绑定random掩盖问题。该回退保证恢复后可继续合法结算，不声称重建宿主未记录的外部闭包随机数状态。独立支付跨审最终5例全部通过。
