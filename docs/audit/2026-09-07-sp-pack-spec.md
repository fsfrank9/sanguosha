# v16 Z1 · SP 3 技实现规格

范围仅为既有 71 将目录中有本地逐字源的【单骑】【庸肆】【伪帝】。其余 SP 技能不随本批增加。单骑沿用既有技能 ID `danji`，未另造 `danqi`。

来源来自已入库的规则镜像 `official-skill-cache/gltjk-sanguosha-rules/pages/`：单骑 `card__hero__wei.md:595`，庸肆和伪帝 `card__hero__neutral.md:621-622`。两条若愚交互判例 `:634-635` 与禁止主公技递归响应条款 `:637` 各自保存整行 SHA-256；测试直接对镜像行逐字验摘要。fixture 与安全缓存只保存结构化规格和摘要，没有捏造官网 gid 或链接。

- **单骑**：准备阶段开始时检查手牌数严格大于体力、主公武将为曹操。满足即觉醒一次，减 1 体力上限，当前体力超过新上限时同步降低，获得马术。复用 `runAwakening` / `grantSkill`。
- **庸肆**：摸牌时多摸当前存活势力数 X 张；弃牌阶段开始时重新采样 X，必须先弃置 min(X, 当时手牌与装备总数) 张牌，再按当下手牌上限弃牌。判定区不在成本范围，因装备失去产生的枭姬等事件走原有移动出口；新摸的牌不扩大已锁定的成本张数。玩家可选择手牌或装备，AI 使用既有弃牌保留价值排序，保留受伤时的救援桃。固政分别登记可归还的弃手牌与可获得的全部弃牌：必须先还一张手牌，之后可获得其余手牌及装备；只弃装备不能触发固政。
- **伪帝**：`viewedLordSkills` 每次读取主公的当前技能数组，`hasLordSkill` 判定当前发动资格。覆盖护驾、激将、救援、黄天、血裔、颂威、暴虐、若愚、制霸。黄天/制霸可显式选择袁术为持有者，对真实主公和袁术分别计算一次额度，UI 和 AI 使用同一资格出口。技能视图不写回自身数组，不产生引用环或 JSON 模拟副本交叉污染。

若愚官方判例的两个顺序均已钉住：

1. 刘禅先觉醒，袁术立即视为拥有并可发动激将。若袁术尚未自行觉醒，刘禅失去技能后袁术的视为拥有完全消失；若袁术也已觉醒，则其自行获得的激将保留在自身技能数组中，但刘禅不再拥有激将后不能发动。
2. 袁术先觉醒，获得的激将暂不可发动。刘禅随后觉醒后，伪帝提供发动资格；刘禅此后失去技能，袁术自有激将仍在，但资格再次消失。

主公可以使用普通牌响应伪帝持有者；原有代打出口只消费该角色自己的牌，不递归调用主公技求助，因此不会借主公的主公技再嵌套一次响应。

这是 **AA 三态技能层之前的局部特例**：只有伪帝涉及的主公技增加读取视图和资格区分，其他技能的拥有/有效性表示保持现有机制。本批不引入通用动态技能存储。

验证包括 24 个引擎场景和 4 个 UI 场景：两条完整若愚顺序判例、技能移除、JSON 副本、九种主公技、装备成本与枭姬、普通手牌上限、同 kind 连续窗口清空选择，以及图鉴状态。旧山包、林包与技能四方一致性检查通过；项目全档验证记录由 Z 阶段总审计文档汇总。

## 暴虐旧基线纠错

伪帝接入暴虐时复核 `card__hero__neutral.md:185`，发现旧林包实现、两条测试和结构化摘要把“其于受到此伤害的角色……扣减体力前为群势力”误读为受伤者势力。这里“其”指前句造成伤害的其他角色，“于……扣减体力前”是采样时机。Z1 在伤害扣血前记录 `sourceCampBeforeDamage`，暂停快照携带该标量；暴虐据此检查来源势力。同步纠正原两条行为钉、林包 fixture/cache 与技能注释，并保留 W2 的伤害致死后仍触发来源时机回归。没有修改暴虐的判定收益或次数。

## 集成守护调整

原 M2 允许 AI 的黄天分支直读一次敌对身份，依据是目标只能为身份公开的主公。伪帝持有者可能身份暗置，该例外不再成立；Z1 改为 `perceivedHostile`，将 ai.js 直读预算由 1 收紧为 0，并校验主公技目标资格仍经共享出口。新增行为钉互换未翻明袁术的真实身份，确认其余观测相同情况下 AI 赠牌选择不变。v6 技能审计仅追加 SP fixture 路径，三项新技能接受原有全部必填规格检查，未放宽覆盖要求。
