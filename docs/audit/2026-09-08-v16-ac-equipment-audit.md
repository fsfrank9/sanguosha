# AC1 域5：十八种装备审计

本轮从 `CARD_CATALOG` 实测装备为 **18 种：12 武器、4 防具、2 坐骑类型**。坐骑具体名称是同类效果的牌面变体；未把赤兔、大宛等重算成独立装备机制。官方镜像中的木牛流马等目录外装备不混入当前分母，木牛仍遵守 Z-G1 的明确范围裁定。

先读取全部 `equipment.js`、装备目录、真实调用点、官方 `card__equipment.md` 和移动/伤害流程。三个最小反例先落入 `tests/v16_ac_equipment_audit.test.mjs`，由根代理独立复跑 **3/3 失败**并核对出处，授权后才修。新增测试最终 **16 例全绿**；相关 15 个旧装备文件 **124 例全绿**，另加生命周期24例，合计17文件164例通过。未以这些旧测试替代新增审计。

## 确证与修补边界

| 编号 | 基线最小观测 | 官方依据 | 窄修与反向检查 |
| --- | --- | --- | --- |
| E1 | 持麒麟弓、`qilin=ask`，目标只有一匹马。真实出杀后直接弃马，不开可放弃的询问。 | `card__equipment.md:113` 的“可以”不因候选只剩一张而消失。 | `ask` 判断先于单马自动分支；新用例在 JSON 恢复后放弃，马仍保留。旧单马自动两例明确设置 `auto`，保留原弃置断言，另有独立 `ask` 反例，未把错误行为改称默认。**这里只关闭可选性缺口，麒麟整体伤害时机另见下述边界。** |
| E2 | 寒冰剑依次弃邓艾两张手牌，目标不受伤，但屯田判定次数为0、田0；应为两次单独失牌各触发一次。 | `card__equipment.md:166`；`card__hero__wei.md:365`；`flow__move.md:58`。 | 新 `hanbing-discard` 响应帧逐张执行，付游标后通知失牌，等该张失牌的屯田/极略及装备失去效果结束再处理下一张。真实两次极略判定各做 JSON 克隆，第一窗前第二张手牌仍在，忍只扣两次。 |
| E3 | 陆逊2体力、装备白银，使用最后手牌八卦；旧日志先白银回血再连营。旧装备提前进入弃牌堆，还能被这次连营洗回摸走。 | `flow__move.md:82,86` 就是陆逊、白银、最后手牌八卦的同一官方示例；`rule__principle.md:104`。 | 先同时撤旧/装新，由新装落位提交最后手牌失去、触发连营，再结算失去装备，最后旧装入弃牌堆。旧装以 `pauseState.equipmentReplacement` 的实体记录留在处理区，空牌堆/空弃牌堆反例不能提前洗回该旧装。 |

E2 不将失牌广播硬塞进所有低级 `takeCard`：否则成本原子提交及返还路径会被错误计为已失去牌。只在已完成的寒冰单次弃置处通知；逐次挂起是修补的一部分，不能仅补两个同步 hook 调用。

最终交叉审查继续挑战 E2 自己的新帧，发现初版在第一张失牌暂停时仍由伤害防止分支提前弃置来源【杀】；这会让尚未结算完的牌参与后续洗牌。新单目标逐窗 JSON 断言先红，根代理独立复跑并核对 `flow__use.md:157` 后授权：寒冰帧用数据持有来源牌，在完成/终局取消时调用统一收牌出口，伤害防止分支识别帧的持有标记。随后多目标四窗口 JSON 对照又揭示统一出口的链保护用了对象相等，第一目标结束时会误弃同 ID 的克隆实体；根代理独立复现并修正统一身份判断，两例均已全绿。两例都保留来源牌在途与最终仅弃一次的断言，不把本轮修补引入的失败归咎于既有测试。

E3 不宣称实现通用装备同时移动调度器。现役替换中的连营、枭姬、白银都是同步落定；本次为确证的同一换装事件修正新旧牌位置及顺序。“直谏替换→回合外屯田→极略”属于本次没有覆盖的可暂停移动组合，需后续统一移动调度批重开，没有以本次陆逊正例推导其已经正确。

## 驳回与明确边界

- “无前只影响原防具注册层，新直接伤害分支会绕过压制”在四种防具的有效/无效八个真实 JSON 对照中被驳回。防具实体仍在装备区，差异来自有效效果出口。
- “AA历史无效马术还会与坐骑双算”被动态切换后到距离2座席的实际距离对照驳回；出向和入向分别检查。
- “只要改E3日志顺序即可”被根代理指出不足：旧白银进入弃牌堆太早会参与连营洗牌。新空牌堆反例证明修补处理的是实体牌位置，并非日志美容。
- 麒麟官方是“造成伤害时”，当前通用 `applyWeaponHitEffects` 仍在伤害收束回调内；致命伤害的求桃窗可能先于麒麟窗，死亡清理还可能先移走目标坐骑。根代理明确裁定为 **AC4 本版收案的既有架构时机限制**，不能宣称官方全等价。重开须新增扣体力前装备时机帧，并覆盖致命命中时的坐骑清理与同一时机多个技能的选择/暂停；本轮九个既有麒麟测试及E1可选性测试不覆盖这些问题。
- 寒冰可选发动沿用既有 `auto/decline` 偏好策略，选牌保持装备优先、其次第一张手牌的既有顺序。根代理明确将逐张人工选牌面板按 **AC4 本版交互边界收案**；逐张失牌挂起已修，不等于拥有完整自由选牌UI。

完整AC门槛、其它域独立挑战、留账最终裁定与部署记录由总验收文档统一记录。
