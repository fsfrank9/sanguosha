### W1-a — AI 反间挂起缺 ok 字段 (做)

`triggerFanjianActiveSkill` 在玩家席猜花色挂起时**裸返**
`{ suspendedForFanjian: true }` —— 没有 `ok` 字段。链路:
`useSkill` 经 `selectActiveSkillResult` 原样上抛 → `aiTakeAction` 读到
`skillResult.ok` 为 `undefined` → `runAITurn` 的
`if (!action.ok) return action` 把这个畸形对象当作**失败结果**返回给调用方。

实测 (改前/改后同一局面):

```
BEFORE-FIX runAITurn → {"suspendedForFanjian":true,"action":"fanjian"} | ok 字段存在: false
AFTER-FIX  runAITurn → {"ok":true,"message":"AI 回合暂停，等待玩家处理选择。","action":"paused"}
```

根因是**返回值语义混用**: `onActiveSkill` 的返回值是**结果** (要带 ok),
不是 hook 信号 (裸对象)。全仓 19 个主动技逐条核对, 只有反间一处如此。
修复与其余一致改为 `success()`, 挂起标记降级为附加字段
(`result.suspendedForFanjian` 仍在, 不破坏任何读它的地方)。

### W1-b — 提示面板表驱动 (做)

`renderPromptPanels` 此前 947 行, 41 段逐字重复的

```js
if (els.XPanel) {
  if (kind === 'k' && pending.actor === 'player') { …填充… }
  else { els.XPanel.hidden = true; }
}
```

问题不在行数, 在**每段都得自己记得写 else 去隐藏**: 漏一处就是"窗口早关了
面板还挂着"; 新增一个 kind 时也没有任何东西提醒你补面板。

改为 `PROMPT_PANEL_SPECS` 注册表 + 统一驱动器 ("先隐藏全部已注册面板, 再只
填充命中的那一个")。41 条按原 if 链顺序**逐条 verbatim 搬运** (机械转换,
不重写 then 体), 8 条带本地态复位的走 `onHide`。41 段结构经脚本核对完全同形
(全部 `pending.actor === 'player'` 闸, 无一条 then 体引用 `kind`), 转换零歧义。

### W1-c① — 克己可选 (做) / 寒冰可选 (已在)

- **寒冰**: `skillPreferences.hanbing` 的 auto/decline 早已存在 → 无事可做,
  记录为"已在"。
- **克己**: 官方逐字「若你未于出牌阶段内使用或打出过【杀】, 你**可以**跳过
  弃牌阶段」(`card__hero__wu.md:61`), 引擎此前**无条件**跳过。

  这已不是全部图景 (例: 想留在弃牌阶段把牌喂给对手的固政; 或单纯不想暴露
  "我这回合没出杀"), 且成本只有一个偏好闸。补 `skillPreferences.keji`
  ('auto' 缺省 → 行为逐字不变; 'decline' → 照常进弃牌阶段)。

### W1-c② — 随机源确定性 + 隐藏横幅 (做)

**randomSuit**: 兜底原本是 `Math.random()`。真走到 (即 `game.random` 缺失)
时同种子复跑会得到不同结果 —— 而整个守恒 fuzz 档的前提正是"同种子必然同轨"。
兜底改为按牌堆+弃牌堆规模取模的**确定性**推导; 有 `game.random` 时行为逐字
不变。同批加静态闸: `src/engine/` 下不得再出现 `Math.random` 作为随机源。

**statusBanner 死 els**: 原表述已过时 —— `statusBanner` 本身不在 `els` 里。
真正的问题是另一件事: `#statusBanner` 整块自 v9 PR-E13 起
`display: none` (`layout.css:209`), 而 `board-panels.js` 每次渲染仍往其中的
`statusTitle` / `statusText` / `deckInfo` 写值, **玩家一个字都看不到**。
三条信息各自的可见去处: 胜负 → 武将卡的状态章 (`playerState`/`enemyState`);
牌堆计数 → `#playerSkillDeckInfo` (v9 PR-E15 迁至技能卡右上)。
裁决: 保留写入 (措辞仍被两个测试钉住, 横幅日后若重新可见即刻复用) 但加存在性
守卫并注明可见去处; **同时把那两个测试的断言补到玩家可见面上** —— 只钉隐藏
横幅等于测试绿而玩家看不见。

### W1-c③ — M9 rollbackRescueCard (收案)

`damage-dying.js` 的 `rollbackRescueCard` 只在
`kind === 'jiu' && responder !== dyingActor` 时触发 (用酒救他人 → 回退不消耗)。
audit4 判定"公共 API 无法构造合法触发路径", 本批复核同结论: 各条救援窗口的
候选构造 (`executeDyingRescue` / 蛊惑处理区路径) 都不会把【酒】列给非自救者。

**收案理由**: 这是一条**防御性**分支, 保护的是牌张守恒红线 (万一未来某条新
路径把酒喂进来, 牌要退回去而不是凭空消失)。要给它写测试就必须绕过公共 API
直调内部函数 —— 那测的是脚手架不是引擎。保留代码 + 注明性质, 不写测试。

### W1-c④ — jsdom 账本 (收案, 但**理由与路线图草稿不同**)

路线图 W1 的草稿理由写的是「fake-dom + Playwright **双层**已等效覆盖」。
本批复核发现这个前提**只对了一半**, 如实更正:

- **Playwright 不是常驻层**。它是 v13 UI 修缮二批的一次性真浏览器验证
  (`docs/history.md:298`), 仓库里**没有任何 Playwright 脚本入库**, `package.json`
  也无相关依赖或脚本。把它算作"第二层"是不准确的。
- **常驻层只有一层, 但这一层是真的**: 23 个 fake-DOM 测试文件、**210 个执行
  用例**, 全部 `import('../src/ui/dom-adapter.js')` 真跑适配层 (不是正则匹配)。
  对照 2026-06-09 当时的账 ("dom-adapter.js 2450 行从未被执行, 52 个测试仅
  正则匹配源码"), 现状是 adapter + panels 共 5673 行 UI 由 210 个执行用例覆盖。

**收案理由 (更正后)**: ① 零依赖是 v15 路线图**非目标**里白纸黑字的红线
(「不引入打包器 / 框架 / jsdom」); ② 引 jsdom 要么加 devDependency 要么手写
DOM shim —— 而手写 shim 正是 `tests/helpers/fake-dom.mjs` 已经做完的事;
③ fake-DOM 层已能捕获真缺陷 —— 本批的 F1 (aoe-sha-response 无面板致卡死)
就是在 fake-DOM 全链路里实测出来的。
**若日后要补第二层, 应作为新立项显式排期, 而不是靠一句既有假设结案。**

## W2 第五轮全量合规审计

### 方法

沿用 audit4 的 12 域并行方法论 (本轮收敛为 10 域): 基本牌与响应链 / 单目标
锦囊 / 多目标锦囊与无懈链 / 延时锦囊与判定区 / 装备 / 魏技能 / 蜀技能 /
吴群技能 / 跨系统矩阵 / 结算顺序专项。每条候选发现**必须附实跑复现脚本与真实
输出** (观察 ≠ 期望), 再逐条经 opus **对抗验证** (默认立场"它是假的": 独立复跑
→ 逐字复核官方镜像 → 排除脚手架 artifact → 排除已归档偏差), 最后跑完备性批判
(哪些对象没被查到 / 哪些声称没被验证 / 哪条驳回可疑)。

模型分配按 CLAUDE.md: 分域清查 sonnet, 对抗验证与完备性批判 opus。

### 确证发现与修复

#### F1 [高] `aoe-sha-response` 窗口在 UI 里没有任何面板 → 整局卡死

引擎在**南蛮入侵 / 借刀杀人需要玩家打出【杀】**且玩家可发动蛊惑时开
`aoe-sha-response` 窗口, 并给出 `options` (含真【杀】)。但:

- 41 个提示面板、4 个响应面板里**没有任何一个**渲染这个 kind;
- 唯一跟着弹出的蛊惑声明面板, 其"取消"钮只清蛊惑自己的暂存, **不收窗口**。

结果: 玩家 (于吉) 被南蛮指定后, 手上有真【杀】也打不出去, 想放弃也放弃不了,
`pendingChoiceGuard` 从此拒绝一切操作 —— **整局卡死**。

fake-DOM 实测 (修复前):

```
窗口: aoe-sha-response | 手上有真杀, options: [{"cardId":"real-sha",…,"name":"杀"}]
点蛊惑面板的"取消"钮 → pending 现在: aoe-sha-response | hp 3 → 3 | 手牌 1 → 1
```

**修复**: 与 `sha-duel-response` 共用决斗响应面板 —— 两者的 resolver 决策形状
本就相同 (`{cardId}` / `{use:false}`)。修复后两条出路实测均通:
打出真杀 → 窗口收、不掉血、杀离手; 点"不出" → 窗口收、受 1 点伤害。

**这条缺陷正是 W1-b 表驱动重构要防的那一类**, 且它此前**没有任何东西能发现**:
新增一个 kind 时忘了配面板, 测试与类型系统都不会吭声。因此同批把不变量做成硬账
(`tests/ui_pending_kind_coverage.test.mjs`): 引擎侧扫 `registerResponseKind`
拿到全部 50 个 kind, UI 侧扫三种渲染路径 (注册表条目 / `kind ===` 直判 /
kind 数组成员), **差集必须为空**, 或落在带理由的显式豁免表里。

#### F2 [中] 反馈是"你可以"但窗口开了下不来

官方逐字 (`card__hero__wei.md:61`):「每当你受到伤害后, 你**可以**获得来源的
一张牌。」引擎:

- `resolveFankuiPickChoice` 只接受 `zone: 'hand' | 'equipment'`, 别的一律
  `setPendingChoice` 重挂;
- UI 面板只渲染区域钮, **没有"不发动"**;
- 唯一的弃权路径是**伤害发生前**就把 `skillPreferences.fankui` 设成
  `'decline'` —— 窗口内无路可退。

身份场里这不是规则洁癖: 司马懿被**队友**误伤时会被迫去偷队友的牌。

**修复**: resolver 补 `{ decline }` 分支 (非法 zone 仍按惯例重挂, 不吞输入
校验); 面板补"不发动"钮并登记为该面板的 `cancelBtn`。三条回归钉:
放弃后来源的牌一张不动 / 照常发动仍能获得一张 (零行为回归) / 非法 zone 仍重挂。
