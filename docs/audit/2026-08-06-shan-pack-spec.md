## spec 提取的两个坑 (如实记录)

1. **蔡文姬有两个同名条目**。山包蔡文姬在 `neutral.md:389`
   (「异乡的孤女」, 群), `wei.md:599` 的「金璧之才」是 **SP 蔡文姬** (魏,
   SP 009)。两者的悲歌逐字相同, 但**断肠不同** —— SP 版是「令杀死你的角色
   失去**你选择的其一张武将牌**的技能」(国战双将体系)。取山包版
   (`neutral.md:393`)。这是 v15 U 的 SP 贾诩同款陷阱, 按同一口径处理:
   **以包归属而非技能名匹配**。

2. **急袭没有独立条目**。它的官方文本内嵌在凿险条目的括注里
   (`wei.md:367` 的「(你可以将一张"田"当【顺手牵羊】使用)」), 没有独立行。
   fixture 里 `sourceTextRef` 与凿险同源, 测试的「行首为技能名」检查对
   `jixi` 显式豁免。它也**不属于任何武将牌的技能列表** —— 只能由凿险觉醒
   授予, 塞进 `HERO_CATALOG.dengai.skills` 会让英雄图鉴谎报邓艾开局三技。
   为此在 `SKILL_METADATA.jixi` 上加了 `grantedBy: 'zaoxian'` 标记, 四方
   一致性审计 (`tests/v6_skill_audit.test.mjs`) 对带该标记的技能改查
   metadata 本体。

## 逐条实现裁定 (S1-S12)

### S1 — 享乐的闸口位置: 有效性检测层, 不是"成为目标时"

官方 `flow__use.md` 的使用时机序把「使用结算内的有效性检测」排在
step 5「指定目标后」**之后**。`sha-flow.js` 的 v14 Q3 注释正是**以享乐判例
为据**把 铁骑/烈弓 的响应锁定前移的 —— 也就是说, 引擎早就为享乐留好了位置。

所以享乐用新 hook `onShaEffectiveness`, 挂在 仁王盾/藤甲 同层、
`computeShaResponseLock` **之后**。可观测差异: 铁骑对刘禅仍会判定
(锁定先于有效性检测), 只是这张杀最终可能因享乐而无效。

### S2 — 享乐的抉择权在**来源**, 不在刘禅

「你**令其**选择是否弃置一张基本牌」—— 掏牌的是杀的使用者。所以:

- AI 来源: `skillPreferences.xiangleCost`(缺省 `auto`) → 弃最不值钱的基本牌;
- **玩家来源**: 开 `xiangle-cost` 窗 (`pauseKey: 'xiangleCost'`), 弃牌放行 /
  decline 则此杀无效。
- 来源已死亡 / 无基本牌 → 直接无效 (官方明写"或其已死亡")。

resolver 收尾时重入 `continueShaAfterCixiong` 带 `presetLock.xiangleSettled`,
否则续跑会二次索要基本牌。

### S3 — 屯田需要一个"失去牌后"时机, 引擎此前没有

官方是「每当你于**回合外失去牌后**」。既有的 `handLoss` 时机是连营专用的
「失去**最后一张手牌**后」, 覆盖不了。新增单点 `notifyCardLoss(game, actor)`
派发 `onCardLost`, 调用点是**牌确实已离开该角色区域之后**的四个出口:

- `takeHandCard` (被顺手牵羊/反馈/巧变等获得手牌)
- `removeTargetZoneCard` (手牌/装备区/判定区任意一张被拆被顺)
- `consumeResponse` (打出闪/无懈等响应牌 —— 回合外失牌的主力来源)
- `recordDiscardPhaseLoss` (弃牌阶段; 屯田自身按"回合外"过滤掉)

**重入保护**: 屯田会在 hook 里判定, 判定牌入弃牌堆 / 被天妒收走都可能再次
走到上面的出口 —— `game.cardLossInFlight` 闸挡住无限递归。

### S4 — "田"是与"创"(不屈) 同形的武将牌上置牌区

新增 `state.tian` 与 `CardRuntime` 的 `'tian'` zone, 并**接入牌张守恒普查**
(`tests/helpers/card-conservation.mjs`) —— 漏掉就等于给了一个造牌/吞牌的口子。

`findOwnCardById` / `removeOwnCardFromAnyZone` 认"田", 但
`firstMatchingOwnCard` (响应牌扫描) **刻意不认** —— 否则"田"里的【闪】会被
自动打出去。急袭是主动转化, 只走前两条路径。

### S5 — 觉醒技是一类新的技能形态: 锁定 + 每局一次

凿险 / 志继 / 若愚 / 魂姿 四技形状完全一致 (准备阶段开始时 → 若<条件> →
<代价/收益> → 获得<新技能>), 抽成共用骨架 `runAwakening`。

它们同时是**锁定**的 (条件满足必须觉醒, 没有"不发动") 和**一次性**的
(`flags.<id>Awakened` 永不复位)。这与 schema 里既有的
"mandatory ⇒ passiveAlways" 不变量冲突 —— 不是把它们错标成 `passiveAlways`
或假装可选, 而是加显式 `awakening: true` 标记, 并把不变量放宽为
「mandatory 且 awakening ⇒ oncePerGame」。

### S6 — 觉醒技授予技能需要一个动态技能写入口

`StateRuntime.grantSkill(state, id, name, meta)` / `stripAllSkills(state)`。
前者服务凿险 (急袭) / 志继 (观星) / 若愚 (激将) / 魂姿 (英姿+英魂),
后者服务断肠。二者都是**单层**写入 —— 化身需要的是三态层, 见文末。

### S7 — 断肠与行殇的先后 ⚠️ **本条已被 v15 W2 第五轮审计推翻并更正**

**本批 (V) 的原裁定是错的, 原文如实保留在下方以便追溯。**

> ~~`SkillRuntime.runHook` 按注册序执行。官方判例是「杀死断肠者的角色**先**
> 失去所有技能」, 所以曹丕杀死蔡文姬时【行殇】已被夺走, 拿不到遗产。~~

这条"官方判例"**没有出处, 而且方向判反了**。W2 逐字复核后的实情:

- 【行殇】与【断肠】是**同一时机** —— `flow__death.md:31`
  「(3) 死亡时：能发动的技能：【行殇】、【藏机】、【挥泪】、【追忆】、
  【断肠】、【随势②】、【延祸】、【武魂②】。」
- 同一时机多名角色的技能, 官方是**从当前回合角色起按逆时针依次** ——
  `glossary__flow.md:30`「…是【化身②】和【连破】的发动时机, **从左慈开始按
  逆时针方向**, 左慈和司马懿(神)依次决定是否发动」。

所以顺序**取决于这是谁的回合**:
曹丕在自己回合杀死蔡文姬 → 从曹丕起算 → **行殇先手**, 他拿到牌, 之后才被
断肠夺技; 曹丕在蔡文姬回合里杀死她 (刚烈/反馈/决斗反伤) → 从蔡文姬起算 →
**断肠先手**, 行殇随技能一起失效。**固定注册序无论选哪边都会在另一种情形
下出错。**

W2 的修复: `settleDeath` 改为经 `runDeathTimingHooks` **逐席派发** (从当前
回合角色起按座次环), 各 handler 只在 `context.resolvingSeat` 命中自己的持有者
时动手; **注册序不再承载任何语义**。两个方向各有回归钉。

`onDeath` 本身在 U 批已前移到 `discardAllZones` **之前**, 两技都复用这一点。

### S8 — 放权需要"额外回合"机制

引擎此前没有额外回合。新增:

- `onBeforePlayPhase` hook (在 `finishDrawPhaseAndAdvance` 与 `advancePhase`
  的 draw→play 两处派发) —— 让技能有机会在 `nextPlayablePhase` 读
  `flags.skipPlay` 之前写它。放权与神速共用这个既有的跳过出口。
- `game.pendingExtraTurns` 队列 + `finishTurnAndAdvance` 单点。额外回合插在
  本回合之后, **结束后回合仍从原回合角色的下家继续** (`extraTurnReturnSeat`),
  不改变座次环推进基准。
- 回合结束时机可能挂起 (玩家选给谁) → `pauseState.turnEndPending` +
  `resumeTurnEndAndAdvance`, 由 `resumeSuspendedTurnFlowIfReady` 最外层续跑。
- 阵亡早退分支同样消费额外回合队列 (放权的受赠者可能正是杀死回合角色的人),
  否则队列永久压着。

### S9 — 固政需要弃牌阶段的逐阶段记账

「其于**此阶段内**因**其弃置**而失去过的手牌」→ 不能只看弃牌堆尾部。
`flags.discardPhaseCards` 在 `setPhase(…, 'discard')` 时清空, 由
`discardSelected` / `discardExcess` 记账, `onDiscardPhaseEnd`
(discard→finish 转换处派发) 消费。传的是**牌对象引用**, 技能侧只认此刻仍在
弃牌堆里的那批 (中途被别的技能拿走的天然跳过)。

### S10 — 制霸被拒绝也计入次数

官方判例 `card__hero__wu.md:305`: 「吴势力角色发动【制霸】与你拼点**被拒绝**
计入其出牌阶段限制的发动次数。」所以 `flags.zhibaUsed` 记在拒绝分支**之前**。

制霸还是继黄天之后第二个「全场型主公技」(技能在主公身上, 由其他座席发动) →
进 `LORD_WIDE_SKILLS`, `useSkill` 的持有校验放宽, 势力/次数/拒绝资格由
handler 自校验。

### S11 — 激昂的两条时机分工互斥

「使用【决斗】或红色【杀】**指定目标后**, 或**成为**其目标后」—— 两个方向、
两种牌。分工:

- 红色【杀】: 走既有 `onShaTargeted` (context 同时带 `sourceActor` 与
  `targetActor`, 一次派发覆盖两个方向);
- 【决斗】: 新增 `onTrickTargeted`, 在 `playJuedouCardHandler` 解出目标后
  派发。

**去重**: `onShaTargeted` 在流离链上会对同一 (杀, 目标) 重跑 → 按
`card.jiangFired[targetActor]` 去重, 否则一次流离转移就多摸一张。

### S12 — 巧变只接入了摸牌阶段分支

官方巧变可跳过「准备阶段和结束阶段除外」的任一阶段, 两个分支各有后续:
跳过摸牌阶段 → 拿两人各一张手牌; 跳过出牌阶段 → 把一名角色判定区/装备区里
的一张牌**置入另一名角色**的判定区/装备区。

本批只接入摸牌阶段分支。跳过出牌阶段那半句需要一个「任意角色判定区/装备区
之间搬运一张牌」的新交互面 (两个角色 × 两个区域 × 一张牌的四段选择), 与本批
其余 15 技无共用基建, 单独立项更清晰。**这是本批唯一的功能缺口, 已在 fixture
的 `deviations` 字段与本节如实登记**, 不是静默省略。

## 左慈成本评估 (路线图明列的独立评估门)

化身官方逐字 (`neutral.md:249` + 后续 `:253/:257/:258/:264` 五条补充说明) 要求:

1. **动态技能三态层**。化身牌上的技能有三种状态 —— 本体技能 / 因化身获得
   且**有效** / 因化身获得但**无效** (`:257`「你获得此技能，同时令你因发动
   【化身】而获得的其他技能无效」)。现有 `state.skills` 是单层数组, 表达不了
   "拥有但无效"。度量: 全仓 **138 处 `hasSkill(` 调用点**, 没有单一裁决入口。

2. **性别与势力覆写单点**。`:264`「你的性别和势力属性视为与你当前选择的
   "化身牌"相同」。度量: 全仓 **11 处直读 `gender` / `camp`**
   (雌雄双股剑 / 离间 / 结姻 / 黄天 / 制霸 / 激将 / 护驾 / 肉林 …),
   **没有任何单点**。要先做覆写层再改这 11 处。

3. **场外武将牌堆**。「随机将两张**游戏外**的武将牌扣置于一旁」——
   本仓 `newGame` 只实例化参战武将, 没有"游戏外武将牌"的概念, 也没有
   出牌/回合开始与结束时更换化身的交互面。

另外 `:253` 还排除了「限定技、觉醒技、主公技以及能令你拥有没有用引号标注的
技能的技能」—— 需要按 `SKILL_METADATA` 的 `frequency`/`awakening`/`lord`
逐条过滤 (这一层本批新加的 `awakening` 标记恰好铺好了)。

**新生**「每当你受到 1 点伤害后，你可以随机将一张游戏外的武将牌置入
"化身牌堆"」—— 脱离化身后**没有任何可观测效果**, 单独实现等于零。

**裁定: 两技一并推迟**, 在 `IMPLEMENTED_SKILL_IDS` 外、fixture 里显式标
`implementationStatus: "deferred"` 并写明 `deferralReason`, 英雄图鉴按
`todo` 渲染 (`tests/ui_hero_browser.test.mjs` 的未实现样本已改用左慈化身)。
把三条横切基建 (动态技能三态层 / 性别·势力覆写单点 / 场外武将牌堆) 独立成
下一批的前置项, 比塞进本批更诚实, 也不会让 15 个已能正确落地的技能陪跑。
