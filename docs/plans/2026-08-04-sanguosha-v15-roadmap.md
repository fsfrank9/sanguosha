林 18 技 / 火 13 技 / 山 17 技 **48 项未实现技能的逐字文本 100% 已在
本地缓存** (48 条 文件:行 逐条复核在案, 如 八阵/火计/看破
`card__hero__shu.md:336/338/340`、化身/新生
`card__hero__neutral.md:249/266`)。红线原文是 "有可靠来源再立项" —
来源已证实存在, 立项条件满足。N3 判定按 "事实误判" 更正, 非重议用户
裁定。

**事实二**: 未实现 69 技中, 48 技 (林/火/山) + 3 技 (SP 关羽单骑/SP
袁术庸肆·伪帝) 本地有逐字源可直接立项; 其余 18 技 (SP 10 将) 本地零

## 总体策略

- 沿用 v12-v14 全程验证的工作规范: 每批独立 PR、`npm run verify`
  全档门禁、行为测试三件套 (引擎+UI+守护)、后台 merge 驱动、推送前
  核对上游 PR 状态、CLAUDE.md subagent 模型分配。
- **方法论增补 (v14 教训固化)**: ① 每批评审收口必含 opus 对抗端到端
  复现 (v14 R-B 牌面伪造级缺陷即由此抓出); ② 新增 UI 测试一律用
  ui-game.mjs 重掷 helper 或显式身份, 禁自写随机开局 (R-B flaky 教
  训); ③ 涉及官方文本的接入批, spec 提取简报随批入库 docs/ (R1 调研
  简报未入库教训)。
- **技能接入批内流水线** (T/U/V 通用): 势力页逐字提取 → 版本基准
  裁定 (标/1V1/3V3/国-标 变体按 1v1+身份场既有口径, 分歧记档如蛊惑
  先例) → 引擎+UI+AI 启发 → 行为测试 → fixture/缓存/图鉴翻转。
  新包 fixture 沿用 wind 样板 (`containsOfficialText:false` +
  sourceTextRef 摘要 + gid 临时编号策略)。
- **红线**: 既有 54 技全部行为测试零改动通过; 三基准门禁不降
  (数字漂移按 "重测回钉" 惯例); 守恒/架构红线快档恒绿。

  收案)。
