## 缘起

v15 用五个阶段把「本地有逐字源的三扩展包」一次吃完 (火 13 技 / 林 18 技 /
山 15 技 + 急袭), 已接入技能 54 → 101; W 批做完第五轮审计并把三条不变量与
守恒 soak 固化入库; X 批把 W 的留账 F8-F14 一次清偿。本次盘点
(内容覆盖 / 文档留账 / 代码留账 / 官方镜像可扩面 四路并查) 得出四个决定
v16 主线的事实:

**事实一 (P0 唯一残余, 且被两个批次点名"留待独立批")**: 全仓现存唯一未修的
P0 是 v15-U 的 **A4「双闪同步循环无挂起停机」** (roadmap:509, 详述
`docs/audit/2026-08-06-lin-pack-spec.md:101`)。它与 v15-S 明文记录的已知局限
**「AI 席在响应窗口不声明蛊惑」** 是**同一个病灶的两个症状**: 响应消费出口
(杀链 / AOE 逐席 / 决斗链 / 濒死链 / 无懈链) 是同步循环, 循环内开不了新窗、
也无停机点。代码侧的自述与之互证 —— `src/engine/guhuo.js:115`「同步调用栈
需要全响应链改造」、`src/engine/tricks.js:174`「响应中声明为已知局限」、
`src/data/skill-status.js:42`「响应窗口打出流程为已知局限」。A4 未修的理由
不是"不重要", 而是**正确改法与 `v10 V3` 架构守护正面冲突**(守护禁止在
sha-flow 手写 `pauseState.shaResponse`), 当时判"强行绕过守护不可取"。
这类"改法已知、被守护挡住"的项**只会越拖越贵**, 且它压着 AI 响应面不能演进。

**事实二 (v15 候选表的一条遗漏 + 逐字源残余已见底)**: v15 缘起的候选来源表
明列 **「SP 单骑/庸肆/伪帝 3 技 — 本次盘点 A 类 (逐字源在库)」**, 但 S/T/U/V/W/X
六批**均未交付**。本次逐条复核确认三条逐字文本确实在库:
【单骑】`card__hero__wei.md:595`、【庸肆】`card__hero__neutral.md:621`、
【伪帝】`card__hero__neutral.md:622` (伪帝另有官方交互判例
`card__hero__neutral.md:634-635` 逐字给出与【若愚】的授予顺序)。
同时对**全部 23 个未接入技能名**逐个 grep 镜像 `card__hero__*.md`: 除
单骑/庸肆/伪帝 与 左慈化身/新生 外, **其余 18 个 SP 技能零命中** —— v15 非目标
第 7 条 (SP 无本地逐字源, 保留"网络环境变更触发回填") 经复核**仍然成立**,
不需重议。结论: 逐字源可直接立项的内容残余只剩 **3 技 + 左慈 2 技**, 内容面
已接近见底 —— 再往前一步就必须过**目录边界门**。

**事实三 (一处数字口径需更正)**: 盘点简报与 README 的"未接入 22 个"经脚本
实测应为 **23 个**。实算: `HERO_CATALOG` 71 将 / 128 条技能槽 / 123 个唯一 id;

**事实四 (横切前置的成本在涨)**: v15-V 的左慈成本评估门度量的是"全仓
**138 处** `hasSkill(` 调用点 / **11 处**直读 `gender`/`camp`"
(`docs/audit/2026-08-06-shan-pack-spec.md:222-229`)。本次实测:
`hasSkill(` 已涨到 **158 处** (skills.js 86 / ai.js 30 / game-engine.js 15 /

含写入与非武将语义, 需按 V 批同口径重算)。**V→X 三批就涨了 20 个调用点** ——
"动态技能三态层"这类单点收口基建, 每晚一个版本就贵一截。这是把它排进 v16
(而不是继续推迟到 v17) 的核心论证。

**事实五 (镜像可扩面的边界形状)**: 官方镜像 `card__hero__*.md` 里还有大量
本地逐字源, 但**全部落在 v15 非目标第 9 条划的目录边界之外**:
神武将 8 将 (`card__hero__legend.md`, 12 个版本条目 / 27 条技能正文, 逐字完整)、
蜀魏吴群支线共 87 名未建模武将、界限突破版 30 条 (shu/wei/wu 各 8 + neutral 6)、
西 1 名 (凯撒, 狼共舞联动)、非游戏 4 名 (唐, 官方自标"非游戏用")。
牌面同理: 未入堆的 3 张锦囊 (以逸待劳/知己知彼/远交近攻) 与 4 件装备
(吴六剑/三尖两刃刀/飞龙夺凤/太平要术) **全是国-标/国-阵/国-势专属**, 与"换座 /
势力明置暗置"一起构成**国战玩法整体未建模**——那是模式级立项, 不是内容缺口。
唯一横跨边界的单点是 **【木牛流马】(界限突破·宝物)**: 逐字源在
`card__equipment.md`, 但它引入全新的"宝物"装备子类与"移出的手牌区", 且会动
"标准+军争 39 牌型"这条已固化的不变量 → 属于**边界裁定题**, 必须设门。

另需注意: 界限突破版**不是"换版本"**。W 批 R1 已确立口径「**换版本的前提是
整张武将牌的技能集一致, 逐条挑版本是无效的**」—— 界限突破普遍改技能集, 因此
它等价于**新增武将条目**, 同样受目录边界门管辖, 不能当作"给现有 71 将升级"
偷渡进来。

### 排序依赖观察

1. **C1 是本版的地基, 必须在最前**。它挡着 C2 (AI 席蛊惑)、C3 (队列快照
   陈旧)、C25 (钩子链无早退) 三条; 而 C10-C13 (左慈线) 会**再往响应链上叠
   一层动态技能查询** —— 先把响应链改成可挂起、再往上加三态层, 顺序反了就
   要返工两次。
2. **C7 (SP 3 技) 是六批遗漏的回收项, 越早清越好**。它规模最小 (0.3 批)、
   逐字源已复核、且【伪帝】"视为拥有主公的主公技"**天然是三态层的一个小样本**
   (`neutral.md:634-635` 的官方判例明确给出"刘禅失去技能 → 袁术也不再视为拥有"
   的动态失效语义)。放在 C10 之前做, 它就是三态层的**先导判例**; 放在之后做,
   等于白丢一个免费的设计输入。
3. **C10-C12 三条横切前置的成本随版本单调上涨** (事实四: 138 → 158)。V 批
   设门推迟是对的 —— 当时它是"山包 15 技之外的额外横切"; 现在内容面见底,
   横切基建**本身就是主线**, 不再和内容批抢容量。
4. **C14 (神将) 是目录边界门, 默认不立项**。v15 非目标 #9 是用户裁定, 不能
   由路线图自行翻案。但门开时它是**最优的下一块内容**: 逐字源 100% 在库、
   规模恰好等于一个火包批、且神将技能 (武神/武魂/涅槃系) 与已接入的
   濒死/标记/判定基建高度互文。故排为"门开即可执行"的备用阶段, 不占默认排期。
5. **C22 (第六轮审计) 殿后**。审计对象必须包含 C1 的响应链改造与本版新增
   内容, 时点才成立 (W 批同款论证)。

**结论排序**: Y 响应链可挂起化 + 低项留账清零 → Z 逐字源残余回收 + 巧变缺口
→ AA 动态技能层 + 左慈门 → AB 目录边界门 (神将包, 默认不开) → AC 收官批。

## 总体策略

- 沿用 v12-v15 全程验证的工作规范: 每批独立 PR、`npm run verify` 全档门禁、
  行为测试三件套 (引擎 + UI + 守护)、后台 merge 驱动、**推送前核对上游 PR 状态**
  (已合并 PR 是终态不可复用)、CLAUDE.md subagent 模型分配 (haiku 检索/清点、
  sonnet 常规实现与测试、opus 复杂定位与对抗验证、主模型仅最高难度裁决)。
- **固定方法论 (v14/v15 教训固化, 全批适用)**:
  ① 每批评审收口必含 **opus 对抗端到端复现** (v14 R-B / v15 T-H1 / v15 V-C2
  均由此抓出); ② 新增 UI 测试一律用 `ui-game.mjs` 重掷 helper 或显式身份,
  禁自写随机开局; ③ 涉及官方文本的接入批, **spec 提取简报随批入库 `docs/`**;
  ④ 三条红线每批复核 —— **牌张守恒 / AI 零全知 / 装备查询单点**;

Y 1-2  →  Z 1  →  AA 1-2  →  [AB 1-2, 门开才执行]  →  AC 1-2
