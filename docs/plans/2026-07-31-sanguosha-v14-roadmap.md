**既定口径, 不再重议** (清查确认为主动产品裁定而非欠账, v14 不当作缺陷
"修复"): 出牌阶段桃仅对自己 (gltjk 变体分歧按用户口径, J0-4 + L 复议维持,
连带救援出牌阶段递桃路径失效); 杀·无双双闪 deferred-ask 口径; 护驾候选叠
身份敌对过滤; M2 零直读白名单 4 处 (主公公开信息豁免); M4 信息性记录之
"无主公 roles × 暗身份组合缺防御断言" (现有 UI 路径不可达, 维持不动;
另一条"借刀立场按持刀者近似"由 Q1 裁决, 不在此列); ES5 `var` 风格
**收案** — 2026-06-09 审计 backlog 的"var→let/const 全量转换"正式裁定不做 (存量风格
统一优先, 转换收益低而 churn 大), 不再出现在后续 backlog。

排序依赖观察 (v12/v13 同款推演):

1. **工程先行, 但只做"越晚越贵"的两件** — P 及其后各批都会新增大量
   测试; harness 不先统一, 新增文件继续复制第 177 份 test() 样板;
   快/全分层不先落地, soak/基准增量会把门禁拖过阈值后被迫返工。其余
   卫生项 (死引用/过时注释/占位钮) 面小, 同批顺带。
2. **多目标杀架构其次** — 方天与流离两笔降级共享同一根因 (单目标
   结算链), 是全仓库唯一确认无后续处理的合规架构缺口; 两技在既有
   3-5 人身份场即有真实候选 (均只需 3+ 席), 无需更大的场即可销账。
3. **AI 深化在多目标之后** — Q 阶段的无懈 EV 与立场建模要把 P 落地
   的多目标杀纳入评估面, 先定架构再调 AI, 避免回炉。
4. **内容/模式批殿后且全部带决策门** — 蛊惑等用户版本裁定, KOF 等规则
   来源核查, UX 池等用户点单; 无裁定/无来源/无点单不动工, 宁缺毋滥
   红线不变。

结论排序: **O 工程清账 → P 多目标杀架构 → Q AI 博弈深化 → R 内容与
模式评估**。(6-8 人大场为 v13 滚动候选, 2026-07-31 用户裁定不做,
5 人封顶收案 — 见非目标。)

## 总体策略

沿用 v11-v13 全程验证的工作规范: 每批独立可合 PR、`npm run verify` 全绿
门禁、行为级回归测试、后台 merge 后开下一批、推送前核对上游 PR 状态、
已合并 PR 不复用; 架构批配守护测试, 交互批引擎+UI+测试三件套同批落地;
每阶段末盘点批对照验收标准。

**方法论增补 (实测修缮批的教训入规)**: 用户实测反馈三大敏感区两轮才
收敛的模式不再重演 —— 每个交互/UI 批的门禁自查清单固定含三项:
① **花色与对比度** (深浅底色上的花色符号逐面板核, 浅底禁用浅灰);
② **官方术语字面** (技能描述与机制逐词对照官方 glossary, "替换≠代替"级
的字面差异按机制差异对待); ③ **询问时机** (该 ask 的时点不得被 auto
路径抢跑; "面板显示陈旧信息 vs 后台状态已变"列入 review 专项)。

全程双红线不变: **1v1 与 3-5 人身份场行为零回归** —— 既有测试零改动
通过。

## 验收标准

- O 后: harness 统一落地 (全量绿、用例数恒等) 或试点后如实记录冻结
  口径; verify 快/全两档可用且 CI 走全档; 卫生小项清零; gid 项收案
  (销账或停止滚动)。
- P 后: 多目标杀矩阵落地, 方天/流离两笔降级销账 (引擎 + UI + 行为测试
  三件套, 另含 AI 目标启发); 单目标全部既有测试零改动通过; 守恒 fuzz
  零失败。
- Q 后: 无懈 EV 五类建模落地且基准胜率门禁不降; 内奸新指标达标;
  Q3 两项实现或收案。
- R 后 (若开工): 蛊惑/KOF 有裁定有来源才动工, 交付则含完整三件套与
  基准回归; 占位入口零"死钮"。
- 全程: 零 npm 依赖、每批独立 PR、推送前核对上游 PR、方法论三区
  自查入每批门禁。

## 非目标

- 不做联网对战 / 房间系统 (本地同屏 + AI 座席不变)。
- 不引入打包器 / 框架 / jsdom (零依赖红线不变)。
- 不做 6 人以上大场 (5 人封顶) — v13 滚动候选经 2026-07-31 用户裁定
  **收案**, 不再滚动为后续版本候选。
- 不重写 UI 视觉体系 (座席环等仅排版扩展, 非视觉重绘)。
- 无可靠官方 spec 来源的技能/牌/模式零接入 (蛊惑未裁定版本不动工,
  KOF 无规则来源不动工)。
- 不做 ES5 `var` 全量转换 (本文档正式收案)。
- R3 候选池未获用户点单不排期。

## 排期与节奏

按 v12/v13 实测节奏 (每批一个 PR、后台 merge 驱动), 合计约 5-11 批:
O 1-2 → P 2-3 → Q 2-3 → R 0-3 (决策门, 可全裁剪)。顺序执行,
阶段内小批推进; P1 多目标矩阵若回归面失控, 允许拆细 (指定/响应/伤害
各一批) 以批次数换确定性。每阶段末盘点批同时是"是否继续下一阶段"的
决策点; R 阶段三个决策门 (蛊惑版本/KOF 来源/UX 点单) 在 O-Q 期间即可
并行征询用户, 不阻塞主线。
